Material PSI 분석 도우미 운영 매뉴얼

매주 월요일 구매팀이 하는 "향후 14주 자재 과부족 점검과 발주 판단"을 이 시스템으로 진행하는 방법을 설명합니다. 앞부분은 전체 운영 흐름, 뒷부분은 10개 Tab 각각의 사용법입니다.

1. 시스템 개요

PSI는 자재가 얼마나 필요하고(Requirement), 얼마나 들어오며(Scheduled Receipt), 그 결과 얼마가 남는지(Balance)를 주차별로 보는 분석입니다. 이 시스템은 생산관리팀의 RTF·Production Plan과 BOM으로 자재 소요량을 자동 계산하고, 재고·입고예정·Open PO와 대조해 어느 자재가 몇 주차부터 부족한지를 보여줍니다.

10개 Tab은 성격에 따라 세 묶음입니다.

묶음Tab성격언제 바꾸나
기준정보1 Material Master · 2 Assy Master · 3 BOM · 4 Safety Stock계속 쓰는 Master Data. 주차와 무관하게 항상 최신값신규 자재·제품, 사양·L/T·BOM 변경이 생길 때마다
주간 데이터5 Inventory · 6 RTF/Production · 7 Open PO · 8 Scheduled Receipt작업 주차(W0)별로 저장. 과거 주차는 그대로 보존매주 월요일 새로 Upload
계산 결과9 Material Requirement · 10 Material PSIUpload 없음. 1~8 데이터로 시스템이 계산10번 화면의 Recalculate를 누를 때만 갱신

계산은 두 기준으로 따로 합니다. 두 결과를 합치지 않습니다.

  1. 기준정보 최신화 (상시)

    Admin · 변경이 생길 때마다

    신규 자재·제품, L/T·Unit·사양 변경, BOM 변경, 안전재고 변경은 생길 때마다 1 Material Master → 2 Assy Master → 3 BOM → 4 Safety Stock 순서로 반영합니다. 월요일 분석 전에 끝나 있어야 결과가 정확합니다.

  2. 새 작업 주차 시작 확인

    자동 · 베트남 시간 월요일 00:00

    새 주차는 빈 상태로 시작합니다. 지난주 데이터는 복사되지 않으며, 지난주 결과는 Snapshot으로 남아 Week 선택에서 조회만 할 수 있습니다.

  3. (필요 시) Weekly Reset

    Admin · 10 Material PSI 화면

    같은 주에 분석을 다시 할 때(예: 월요일 분석 후 수요일에 변경된 재고·발주로 재분석) 이번 주 5~8번 데이터를 비웁니다. 지난 데이터와 섞이는 것을 막기 위한 단계입니다. 처음 분석하는 주에는 하지 않아도 됩니다.

  4. 주간 데이터 Upload

    Admin · 월요일 오전

    각 Tab의 Template으로 이번 주 주차 Header가 들어간 빈 양식을 받아 채운 뒤 Upload합니다. 권장 순서:

    1. 5 Inventory — 월요일 아침 재고 (Material + Assy)
    2. 6 RTF/Production — 생산관리팀 게시 파일의 RTF·생산계획 14주
    3. 7 Open PO — 잔량 0인 PO 포함 전체 PO
    4. 8 Scheduled Receipt — 업체와 협의한 주별 입고예정 (반드시 Open PO 다음)

    각 Upload는 검증 결과 화면에서 [Apply (반영)]을 눌러야 저장됩니다.

  5. Recalculate

    Admin · 10 Material PSI 화면

    우측 상단 Recalculate를 누르면 1~8 데이터로 9·10번을 다시 계산합니다. 완료 메시지와 함께 Final Calculation 시각이 바뀌고 ● Need Recalculation이 사라집니다. Error가 있으면 계산하지 않고 이전 결과를 유지합니다(8장 참고).

  6. 결과 확인과 구매 판단

    구매 담당자 전원 · 조회

    10 Material PSI에서 자재별 과부족을 보고, 필요하면 9 Material Requirement에서 어느 Assy 때문에 소요가 생겼는지 확인합니다. 판단 기준은 4장에 있습니다.

  7. 발주·납기 조정 후 재분석

    담당자 → Admin

    신규 PO를 내거나 업체와 납기를 바꾸면 Open PO·입고예정 파일을 고쳐 다시 Upload하고 Recalculate합니다. 원칙적으로 정기 발주는 월요일, 이후에는 특별한 사유가 있을 때만 긴급 발주합니다.

기준정보(1~4)를 바꾸면 9·10번 결과는 바로 바뀌지 않습니다. 화면에 ● Need Recalculation이 뜨며, Recalculate를 눌러야 반영됩니다.

4. PSI 판독과 구매 판단

10 Material PSI는 자재 하나, 기준(RTF / Prod.) 하나마다 4행을 보여줍니다.

행계산
Requirement9번 Total 행과 같은 주별 소요량
Scheduled ReceiptManual(검정) + Calculated(파랑) 입고예정. 셀에 마우스를 올리면 구성 표시
Inventory Balance주차 t = 기초재고 + Σ입고예정(W0~t) − Σ소요량(W0~t)
PO Balance주차 t = 기초재고 + Open PO 전량 − Σ소요량(W0~t). 입고예정은 더하지 않음

판단 기준

상황뜻조치
PO Balance 음수이미 발주한 수량을 다 받아도 부족신규 발주. 음수가 처음 나오는 주차와 L/T를 보고 발주 시점·수량 결정
Inventory Balance 음수, PO Balance 0 이상수량은 발주돼 있으나 입고가 늦음납기 당김 검토. 업체와 협의해 입고예정을 앞당기고 8번 재Upload
Scheduled Receipt에 파란 숫자가 큼업체와 확정하지 않은 Open PO 잔량을 L/T 주차에 가정함업체와 실제 납기를 확정해 8번에 Manual로 올리면 파란 값이 줄어듦
둘 다 0 이상14주 동안 부족 없음조치 없음. 과잉재고 여부만 확인
v1.0에는 발주필요수량 자동 계산, MOQ, 발주 제안 기능이 없습니다. 발주 수량은 PSI 결과를 보고 담당자가 판단합니다.

6. 화면 공통 사용법

조회

  • Week (5~10번): 작업 주차 선택. 기본은 이번 주(W0), 지난 16주까지 선택 가능. 과거 주차는 조회·Download만 되고 Upload·Recalculate는 막힙니다
  • Status (1~4번): 기본 Active. All / Inactive / No DB로 바꿔 조회
  • Plan (6·9·10번): All / RTF / Prod.
  • Search by + Keyword → Search: 부분일치, 대소문자 무시

Upload

  1. Upload 클릭 → (1~3번만) Upload Type 선택 → 파일 선택 → Upload
  2. 검증 결과 화면에서 건수(신규·수정·교체 등), Error·Warning 목록 확인. Download validation result로 목록을 Excel로 받을 수 있음
  3. Apply (반영)을 눌러야 저장. Error가 1건이라도 있으면 반영 버튼이 없고 아무것도 저장되지 않음
  • 지정 시트명만 읽습니다. 하나의 파일에 여러 시트가 있어도 됩니다
  • 1행 = Header(이름이 정확히 같아야 함, 순서 무관). 2행부터 데이터. 병합 셀·제목 행·합계 행 금지
  • 수식은 계산 결과값을 읽습니다. 숫자 Code(예: 4605000219)는 문자열로 처리. 3.04E+11처럼 손상된 Code는 Error
  • 빈칸과 -는 빈 값(수량은 0)
  • 다른 사람이 같은 Tab에 Upload 중이면 "Another user is uploading" 안내 후 거절

Download · History · Template

  • Download: 현재 조회조건의 전체 행. 대부분 그대로 고쳐서 다시 Upload할 수 있는 형식
  • History (1~4번): 조회된 Code의 과거 변경 이력과 변경 시점 값
  • Template (5~8번, Admin): 이번 주 주차 Header(YYYY-Www 14개)가 들어간 빈 양식

7. 10개 Tab 상세

1. Material Master Master DB · /material-master/

구매 자재의 기준정보. 다른 모든 Tab이 Desc.·Spec.·Unit·L/T·Status를 여기서 가져옵니다.

Upload 시트
MD_Material: Material Code, Desc., Spec., Unit, Purchaser ID, Vendor, Country, L/T(Weeks)
Upload Type
Add 신규만 등록(기존 Code는 무시) · Change 기존 덮어쓰기 + 신규 등록 + Inactive 재활성화 · Inactive 파일의 Code를 Inactive로(Code 열만 사용)
필수 규칙
Material Code 중복 불가(대문자로 저장) · Unit 필수(EA, SHEET, SET, G, KG, MM, M) · L/T 필수, 1 이상 정수 · Purchaser ID는 등록된 사용자 ID · ASSY는 Code로 사용 불가
화면 수정
Admin이 값을 고치면 행이 자동 체크되고 수정 칸이 노랗게 표시 → Save(체크된 행만 저장). Status를 Inactive로 바꾸는 것도 여기서. 신규 Code는 Upload로만
주의
Unit을 바꾸면 기존 BOM의 Unit과 달라져 Recalculate가 Error가 됩니다. BOM도 함께 바꿔 다시 Upload하세요. L/T를 바꾸면 8번 Calculated 입고예정 주차가 바뀝니다.

2. Assy Master Master DB · /assy-master/

노바텍이 생산·납품하는 제품의 기준정보. Key는 고객사 품번 Customer Code입니다.

Upload 시트
MD_Assy: Customer Code, Assy Code, Type, Model, Item, Customer, Country
Upload Type
Add / Change / Inactive (1번과 같음)
필수 규칙
필수는 Customer Code뿐 · Customer Code 중복 불가 · Assy Code는 참고용이라 중복 허용, 같은 값의 Material Code가 있어도 됨 · Assy Unit은 EA 고정
화면 수정
1번과 같은 방식 (Assy Code, Type, Model, Item, Customer, Country, Status)

3. BOM Master DB · /bom/

Assy 1개에 들어가는 자재와 소요원수. 9번 소요량 계산의 기준입니다.

Upload 시트
BOM: Customer Code, Material Code, Unit, Q'ty
작성법
Assy마다 Material Code에 Assy라고 쓴 행으로 시작하고 그 아래에 자재 행을 이어 씁니다. 같은 Customer Code 행은 붙어 있어야 합니다. 같은 자재가 여러 행이어도 되고, 계산 때 합산됩니다
Upload Type
Add BOM이 없는 Assy만 등록 · Change 파일에 있는 Assy의 BOM을 통째로 교체(이전 BOM은 History로). 파일에 없는 Assy는 그대로. 삭제 기능 없음
필수 규칙
자재 행 Unit이 Material Master Unit과 같아야 함 · Q'ty는 0보다 큰 숫자 또는 분수(0.02, 1/50). Excel이 1/50을 날짜로 바꾸면 Error → 셀을 텍스트 서식으로 하거나 소수로 입력 · 자재 행이 없는 Assy는 무시(기존 BOM 유지)
화면
현재 BOM만 표시. Status 필터는 Assy 기준(All / Active / Inactive / No DB). Mat. Code로 검색하면 그 자재를 쓰는 Assy BOM이 나옴. 화면 수정 없음

4. Safety Stock Master DB · /safety-stock/

Assy별 안전재고. RTF 기준 14주차(W+13) 소요량에만 더해집니다. Prod. 기준에는 반영하지 않습니다.

Upload 시트
SAFETY: Customer Code, Safety Q'ty
Upload 방식
전체교체. 파일에 없는 Code는 삭제됩니다. 바뀐 행만 History(Add / Change / Delete)에 남음
필수 규칙
0 이상의 정수 · 빈칸은 0 · Customer Code 중복 불가
참고
6번에 RTF·Prod.가 모두 없고 Safety만 있는 Assy는 Recalculate 때 RTF(14주차 = Safety)·Prod.(0) 행이 자동 생성됩니다

5. Inventory Weekly Data · /inventory/

작업 주차 월요일 아침 재고. 원자재·재공 구분 없이 합계만 관리합니다.

Upload 시트
INVENTORY: Category, Code, Unit, Stock Q'ty
Upload 방식
이번 주 재고 전체교체 (과거 주차 데이터는 보존)
필수 규칙
Category는 Assy 또는 Material · Assy는 Code에 Customer Code, Unit은 빈칸 또는 EA · Material Unit은 Material Master와 같아야 함 · 0 이상, 소수점 6자리까지 · Category + Code 중복 불가
계산 쓰임
Material 재고는 RTF·Prod. 기초재고 모두에, Assy 재고는 BOM으로 환산해 RTF 기초재고에만 더함

6. RTF/Production Weekly Data · /rtf-production/

생산관리팀의 Assy별 출하계획(RTF)과 생산계획(Prod.) 14주.

Upload 시트
RTF 그리고/또는 PROD_PLAN: Customer Code, Plan, 주차 14개(2026-W48 … 2027-W08처럼 이번 주부터 연속)
Upload 방식
파일에 있는 시트의 Plan만 이번 주분 교체. RTF만 올리면 RTF만 바뀜
필수 규칙
Plan 값: RTF 시트는 RTF, PROD_PLAN 시트는 Prod. 또는 Production · 0 이상의 정수 · 주차 Header가 이번 주부터 14주가 아니면 Error · Customer Code 중복 불가
화면
마지막 열 Safety(W+13): RTF 행은 업로드 값 + Safety Stock. 한쪽 Plan만 있는 Assy는 다른 쪽이 0으로 자동 생성. BOM이 없으면 No BOM 열에 NO
Download
업로드 원본값(Safety 합산 전)으로 RTF·PROD_PLAN 시트에 나뉘어 받아짐

7. Open PO PO · /open-po/

발주했지만 아직 입고되지 않은 수량. 잔량 0인 PO까지 전체 PO를 올리면 시스템이 계산합니다.

Upload 시트
OPEN_PO: PO Date, PO No, Material Code, Unit, PO Q'ty, Currency, Unit Price, Cancel, G/R, In Transit, Vendor
자동 계산
Final PO = PO Q'ty − Cancel · Remain Q'ty = Final PO − G/R − In Transit · Amount = PO Q'ty × Unit Price · Open PO = In Transit + Remain (0보다 큰 행만 사용)
필수 규칙
PO Date(yyyy-mm-dd), PO No, Vendor 필수 · PO Q'ty 0 초과 · 수량·단가 소수점 6자리까지 · Unit Price를 넣으면 Currency(USD, KRW, VND, CNY, JPY) 필수 · Remain이 음수면 Error · 이미 올린 입고예정이 이 Open PO보다 크면 Error

8. Scheduled Receipt PO · /scheduled-receipt/

업체와 협의한 Material + Vendor별 주차 입고예정. 운송 중(In Transit) 물량의 도착 예정분도 여기에 넣습니다.

Upload 시트
SCHED_RECEIPT: Material Code, Vendor, Unit, 주차 14개
필수 규칙
Open PO를 먼저 Upload · Material + Vendor당 1행(같은 업체 일별 입고는 주별로 합산) · 14주 합계가 그 Material + Vendor의 Open PO보다 크면 Error · 0 이상, 소수점 6자리까지 · Vendor 대소문자 무시
자동 입고예정
차이분 = Open PO − 입력한 14주 합계. 0보다 크면 작업 주차 + L/T 주차에 파랑으로 더함(W+13을 넘으면 W+13). Master에 없는 자재는 L/T가 없어 계산하지 않음
Download
입력한 Manual 값만 (파란 계산값 제외)

9. Material Requirement Report · /material-requirement/

자재별 주차 소요량. Upload 없이 Recalculate 결과를 조회합니다.

계산
Σ(Assy 주별 계획 × BOM 소요원수). RTF 행 14주차는 (RTF + Safety) × 소요원수. 재고·PO·입고예정은 쓰지 않음
화면 구조
자재·Plan마다 Total 행(자재 합계, Desc./Spec.)과 그 아래 Assy 행(Assy별 소요, Type/Model, 소요원수)
검색
Mat. Code 또는 Cust. Code(그 Assy가 속한 자재 묶음 전체 표시)
표시
화면은 소수점 2자리, Download는 계산 원본 10자리. 상단에 "BOM 미등록 Assy n건 – 소요량 0 간주" 경고

10. Material PSI Report · /material-psi/

최종 분석 화면이자 Recalculate·Weekly Reset을 실행하는 곳입니다.

화면 구조
자재 × Plan마다 Requirement / Scheduled Receipt / Inventory Balance / PO Balance 4행. Opening Inventory, Open PO 열은 기준별 값. Open PO 셀에 마우스를 올리면 PO No·날짜·수량
Recalculate
Admin, 이번 주만. 1~8 저장값으로 9·10번 계산. 계산 전 점검에서 Error(BOM Unit 불일치, 입고예정 > Open PO)가 있으면 중단하고 이전 결과 유지. 동시에 한 사람만 실행
Weekly Reset
Admin, 이번 주만. 확인 창 → Confirm 시 이번 주 5~8번 데이터 삭제 → "Upload new weekly data in this week." 안내. 1~4번과 과거 주차는 그대로, 9·10번은 다음 Recalculate까지 이전 결과 유지
Operation log
Recalculate·Weekly Reset 기록과 마지막 계산의 Error·Warning 상세를 Excel로

Error는 해당 Upload 또는 계산 전체를 멈춥니다. 고친 뒤 다시 실행하세요. Warning은 처리는 그대로 되고 목록으로만 알려줍니다.

메시지 (요지)등급원인과 조치

9. 자주 묻는 질문

Upload했는데 9·10번이 그대로입니다

9·10번은 Recalculate를 눌러야 갱신됩니다. 화면 상단 ● Need Recalculation이 그 표시입니다.

월요일인데 5~8번이 비어 있습니다

새 작업 주차는 빈 상태로 시작합니다. 이번 주 데이터를 Upload하세요. 지난주 내용은 Week에서 지난 주차를 고르면 볼 수 있습니다.

Upload 버튼이 회색입니다

Admin이 아니거나, Week에서 과거 주차를 선택한 경우입니다.

Weekly Reset을 잘못 눌렀습니다

이번 주 5~8번 데이터만 지워집니다. 같은 파일을 다시 Upload하고 Recalculate하면 복구됩니다. 9·10번 결과는 Recalculate 전까지 남아 있습니다.

Material Master에 없는 자재가 PSI에 나옵니다

BOM·재고·PO에만 있는 Code도 계산에 포함하고 No DB로 표시합니다. 1번에 등록하면 Desc.·Spec.이 채워지고, 8번 자동 입고예정도 계산됩니다(L/T 필요).

과거 주차 결과가 지금 Master 변경으로 바뀌나요?

아니요. 과거 주차 계산값은 그때 Snapshot으로 남습니다. 다만 화면의 Desc.·Spec. 같은 설명 문구는 최신 Master 값으로 보입니다.
