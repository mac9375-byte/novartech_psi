## 2. 시스템 구조 (초보자용 그림)

```
브라우저 (http://localhost:8000)
   │  화면 요청 / 버튼 클릭
   ▼
Django (Python 웹 프로그램, 내 PC에서 실행)
   ├─ 화면(HTML)을 만들어 보내고
   ├─ 모든 요청마다 "로그인했는지 · 권한이 있는지"를 서버에서 검사하고 (Ⅰ-9)
   └─ DB에 읽고 쓴다
   ▼
PostgreSQL (DB, 내 PC에서 실행)
```

- 화면은 Django가 서버에서 HTML로 만든다. 별도 React 앱을 두지 않는다. `ponytail: 표 편집이 무거워지면 표 라이브러리만 추가`
- 화면 문구는 영문 기본 (Ⅳ-3-4).

### 폴더 구조 (예정)
```
novatech_psi/
  manage.py            ← Django 실행 명령의 입구
  config/              ← 설정 (DB 연결, 시간대, 세션 2시간 등)
  accounts/            ← 이번 범위: 계정·로그인·권한·User Management
  templates/           ← 화면(HTML)
  static/              ← 화면 꾸밈(CSS)
  .env                 ← DB 비밀번호 등 비밀값 (Git에 올리지 않음)
  설계/                 ← 설계 문서
```
Module 1~10은 이후 각 Module 승인 시 폴더를 추가한다. (Ⅰ-5 확장성)

## 3. DB 설계 (이번 범위)

### 3-1. `accounts_user` (사용자 계정)
| Column | 형식 | 규칙 |
|---|---|---|
| id | 숫자 (자동) | 내부 번호 |
| username | 문자 150 | **Purchaser ID**. Unique, 소문자 저장, 영문·숫자·`.`·`_`·`-` (H-2) |
| password | 문자 | **Hash 값만 저장** (Django 기본 PBKDF2 방식). 평문 저장 없음 |
| name | 문자 100 | 필수 |
| email | 문자 254 | 필수, e-mail 형식 |
| tel | 문자 30 | 선택 |
| user_class | 문자 | MASTER / ADMIN / USER / GUEST. Sign up 시 USER |
| id_status | 문자 | REQUESTED / APPROVED / DISABLED. Sign up 시 REQUESTED |
| must_change_password | 참/거짓 | 임시 P/W 상태. 참이면 새 P/W 저장 전 업무 화면 차단 |
| failed_login_count | 숫자 | 연속 실패 횟수. 성공 시 0 |
| locked_until | 일시 | 5회 실패 시 지금 + 10분 |
| password_reset_at, last_login, created_at, updated_at | 일시 | **UTC 저장** |
| version | 숫자 | Optimistic Lock용. Save할 때마다 +1 (Ⅰ-11) |

### 3-2. Django 기본 테이블
- `django_session`: 로그인 세션 (2시간 미사용 시 만료)
- `django_migrations`: DB 구조 변경 이력 (자동)

> Migration: DB 표 구조를 코드로 기록해 두고 명령 한 번으로 만들거나 바꾸는 기능. 표를 손으로 만들지 않는다.

`ponytail: 감사 기록(audit) 테이블은 Upload·Recalculate가 생기는 Module 1부터 추가`

## 4. PostgreSQL 설치 및 DB 준비

1. 사용자가 PowerShell에서 아래 명령을 실행한다. (관리자 권한 확인 창이 뜨면 "예")
   ```
   winget install --id PostgreSQL.PostgreSQL.17 -i
   ```
   `-i`: 설치 화면을 띄워서 사용자가 **postgres 관리자 비밀번호를 직접 정한다.** 포트는 기본값 5432 유지.
2. 설치 후 프로젝트 전용 DB `novatech_psi`와 전용 계정 `novatech_app`을 만든다. (관리자 비밀번호는 사용자가 직접 입력, AI는 보관하지 않음)
3. 전용 계정 비밀번호는 개발용으로 새로 만들어 `.env` 파일에만 저장한다.

## 5. 화면 · URL 설계

| 화면 | URL | 접근 | 주요 동작 |
|---|---|---|---|
| Log-in | `/login/` | 누구나 | ID, Password → Log In / Sign up 링크 |
| Sign up | `/signup/` | 누구나 | ID + **ID check** 버튼, P/W, P/W Again, Name, e-mail, Tel → Save → "승인 대기" 안내 |
| Main | `/` | 로그인 | 10개 Module 메뉴(그룹: Master DB 1~4 / Weekly Data 5~6 / PO 7~8 / Report 9~10), 우측 상단 User ID · ID info · Log out, Master만 **※ User Management** 버튼 |
| ID Info (Pop-up) | `/me/` | 로그인 | 본인 Name, e-mail, Tel, P/W(Old P/W 확인) 변경. 임시 P/W 사용자는 자동 표시, Old P/W 대신 임시 P/W 입력 |
| User Management | `/users/` | **Master만** | 표: Check / Purchaser ID / Name / Class / ID Status / e-Mail / Tel. Class·ID Status 수정 → Row 선택 → Save. Row 선택 → P/W Reset |
| Log out | `/logout/` | 로그인 | 세션 종료 → Log-in 화면 |

- Main의 Module 메뉴는 아직 만들지 않은 Module은 비활성(회색)으로 표시하고, Module이 완성될 때마다 활성화한다.
- 모든 화면의 시간 표시는 **브라우저 Timezone 기준**으로 변환한다. (브라우저가 알려주는 Timezone을 저장해 사용) `[권장안]`

## 6. 업무 규칙 구현 방식

| 규칙 | 구현 |
|---|---|
| Approved만 Log-in (Ⅴ-2) | Log-in 시 Password 확인 후 id_status 검사. Requested/Disabled는 같은 실패 메시지가 아닌 "승인 대기" / "사용 중지된 ID" 안내 `[권장안]` |
| 5회 실패 10분 잠금 (Ⅴ-1-7) | failed_login_count, locked_until으로 처리. 잠금 중 지정 메시지 표시 |
| 2시간 미사용 자동 Log-out | 세션 유효시간 2시간 + 요청할 때마다 연장 |
| 권한 검사 (Ⅰ-9) | 권한표를 **한 곳**(`accounts/permissions.py`)에 정의하고, 모든 저장·Upload·관리 요청은 서버에서 이 표로 검사. 버튼 비활성화는 화면 편의용일 뿐 |
| 임시 P/W 강제 변경 | must_change_password = 참이면 ID Info와 Log out 외 모든 URL을 ID Info로 돌려보냄 |
| P/W Reset (Ⅴ-5) | 무작위 임시 P/W 생성 → Hash 저장 → e-mail 발송. **PoC에서는 실제 발송 대신 실행 터미널 화면에 출력** `[권장안]` (설정 1줄로 회사 메일로 전환) |
| Master 초기 계정 (Ⅴ-1-1) | 설치 명령 1회 실행 → 무작위 임시 P/W를 화면에 1회 출력, must_change_password = 참. 소스코드에 P/W 없음 |
| Optimistic Lock (Ⅰ-11) | User Management Save 시 조회 당시 version과 DB version 비교, 다르면 저장하지 않고 안내 후 재조회 |
| Master 자기 자신 보호 | Master는 자기 Row의 Class·ID Status를 바꿀 수 없음 `[권장안]` |
| User Management 검색 | 20명 규모라 검색 없이 전체 표시 `[권장안]` |

## 7. 테스트 계획
자동 테스트(코드로 된 점검표)로 `설계/01` A-14의 8개 시나리오를 모두 검사한다.
1. Sign up → Requested → Log-in 실패
2. Master 승인 → Log-in 성공
3. 5회 실패 → 10분 잠금 → 성공 시 실패 횟수 초기화
4. P/W Reset → 임시 P/W 로그인 → 업무 URL 차단 → 새 P/W 저장 후 해제
5. Guest/User/Admin이 User Management URL·저장 요청 직접 호출 → 거부
6. Disabled Log-in 실패
7. 세션 만료 설정 2시간 확인
8. DB에 평문 Password 없음
+ ID 규칙(H-2: 대문자 입력 → 소문자 저장, `.`·`_`·`-` 허용, 공백·기타 특수문자 Error), P/W 규칙, Optimistic Lock 충돌

추가로 브라우저에서 직접 화면을 열어 Log-in → Main → User Management 흐름을 확인한다.
